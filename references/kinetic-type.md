# 키네틱 타이포

글자·단어가 주인공인 영상(가사, 대사, 매니페스토, 카피)의 모션 수치와 연출 규칙, 그리고 JIZURA 브라우저 앱으로 초안을 뽑는 절차.

출처는 JIZURA(github.com/852wa/JIZURA, MIT)의 소스다. 2026-10-08에 `src/05_anim.js`, `src/01_util.js`, `src/11p_kinetic1.js` 앞부분과 README를 읽고 뽑았다. 나머지 팩은 읽지 않았으므로 아래 수치는 "이 도구가 쓰는 값"이지 유일한 정답이 아니다. 출발점으로 쓰고 화면을 보고 조정한다.

## 1. 모션 수치

### 이징은 비대칭으로

| 구간 | 이징 | 비고 |
|---|---|---|
| 등장 | `outExpo` | 빠르게 들어와 길게 안착 |
| 퇴장 | `inCubic`, 강하게는 `inExpo` | 천천히 출발해 가속 |
| 와이프·카메라 전환 | `inOutExpo`, `inOutCubic` | 양끝이 모두 보이는 움직임만 |
| 팝 | `outBack` 오버슈트 2.6 | 기본값 1.9보다 세게 |
| 블러·페이드 | `outCubic` / `inQuad` | 알파는 `pow(e, 0.7)`로 조금 먼저 올린다 |

등장과 퇴장에 같은 곡선을 쓰지 않는다.

### 글자별 스태거

- 딜레이는 등장 시간의 **40–45%**에 분산하고, 각 글자의 움직임은 나머지 **55–60%**를 쓴다.
- 순차 딜레이(`i/(n-1)`): 팝, 회전, 타이핑처럼 읽는 방향이 중요한 것.
- 랜덤 딜레이(`hash(seed, i)`): 낙하, 분해, 비산처럼 흩어지는 것.
- 스크램블은 뒤 글자일수록 늦게 확정한다(`0.25 + 0.75·i/(n-1)`).

### 레시피 값

| 레시피 | 값 |
|---|---|
| 팝 | 스케일 `outBack(q, 2.6)`, 회전 ±28°에서 0으로 |
| 낙하 | 글자 크기의 2.4배 위에서 바운스, 세로 +50%·가로 −20% 스쿼시가 풀림 |
| 늘이기 | 가로 4.2배 → 1, 잔상 4장 |
| 블러 인 | 블러 26 → 0, 크기 1.18 → 1, 자간 +0.5 → 0 |
| 줌 인 | 크기 1.7 → 1, 블러 14 → 0, 알파는 앞 25%에 다 올림 |
| 회전 인 | ±200° → 0, 스케일 0.15 → 1 |
| 슬라이스 | 가로 띠 7개가 좌우 교대로 화면 폭 0.9배에서 들어옴, 띠마다 5% 지연 |
| 비산 퇴장 | 화면 폭 0.7배 거리, 회전 ±540°, 스케일 +80% |
| 붕괴 퇴장 | 중력 `H·5.5`, 무너지기 **0.25초 전부터** 글자 크기 1.2% 떨림 |
| 수축 퇴장 | 크기 −96%, 자간 −0.2 |

### 유지(홀드) 구간

가만히 두지 않되 읽기를 방해하지 않는 크기로.

- 호흡: 크기 ±3.5% (0.9Hz), 자간 ±0.03 (0.6Hz). 두 주파수를 다르게 둔다.
- 드리프트: 컷 길이 동안 화면 폭의 3.5% 이동, 크기 +5%.
- 웨이브: 세로 ±7%, 회전 ±5°, 글자당 위상 0.75rad.
- 지터: 글자 크기의 2.5%, 회전 ±4°.

### 착지 충격

새 단어가 들어올 때 이미 있던 단어가 반응해야 무게가 생긴다.

- 기존 줄의 재배치: `outExpo` 0.34초.
- 새 단어 등장: 0.24초. 스케일 2.6배에서 축소, 또는 화면 높이 0.7배 위에서 낙하, 또는 옆에서 폭 0.9배 슬라이드.
- 밀림: 착지 0.12초 뒤 `exp(-9t)·cos(26t)`, 진폭은 새 단어 크기의 7%, 0.6초 안에 끝낸다.
- 일반 감쇠 스프링 기본값: `exp(-7t)·cos(18t)`.

### 단어 추적 카메라

- 단어마다 카메라 상태를 만든다: 그 단어가 수평으로 읽히게 회전, 중앙 정렬, 화면 폭 76%에 맞춰 줌.
- 전환은 `inOutCubic` 0.36초.
- 줌은 로그 보간(`exp(lerp(log a, log b, e))`)으로 한다. 선형 보간은 줌아웃 쪽이 급해 보인다.
- 전환 중간에 22% 줌아웃 딥(`1 − 0.22·sin(πe)`)을 넣어 이동 거리를 보여준다.
- 마지막에 전체가 보이는 오버뷰로 0.5초에 걸쳐 빠진다.

### 속도 기반 스미어

이징의 프레임 간 차분(`e(t) − e(t − 1/fps)`)에 이동 거리를 곱해 속도를 구하고, 진행 방향으로 늘인다. 상한 2–2.4배. 별도 모션 블러 없이도 속도감이 난다.

### 코마(스텝) 단위 랜덤

- 지터·글리치·깜빡임의 난수 키는 프레임 번호가 아니라 **스텝 번호**(12fps = 2코마)에 묶는다. 60fps로 렌더해도 깜빡임 속도가 같다.
- 2코마(12/초)는 문자 PV 특유의 딱딱 끊기는 느낌, 3코마(8/초)는 더 작화풍, 풀프레임은 카메라 이동과 흐르는 띠에 쓴다.

### 단어 온셋과 박자

- 기본: 컷 앞쪽 **42–50%** 구간에 단어를 0.32–0.5초 간격으로 균등 배치. 뒤쪽 절반은 읽는 시간이다.
- 박자가 있으면: 직전 온셋과 0.2초 이상 떨어지고 컷의 72% 안에 있는 박자를 순서대로 골라 온셋으로 쓴다. 조건에 맞는 박자가 모자라면 균등 배치로 돌아간다.
- 한 컷의 단어 묶음은 2–6개. 넘치면 가장 짧은 이웃 쌍을 합치고, 모자라면 가장 긴 것을 가운데에서 쪼갠다.

### 결정적 랜덤

모든 난수는 `hash(seed, 글자 인덱스, 채널 번호)`로 만든다. 프레임 순서와 무관하게 같은 값이 나와야 seek(t) 렌더가 흔들리지 않는다. `Math.random()`은 쓰지 않는다. craft.md의 결정적 렌더링 규칙과 같은 이야기다.

레시피는 글자별 변환(`dx, dy, rot, s, a`)을 반환하게 하고 합성 규칙을 고정한다: 이동·회전은 더하고, 스케일·알파는 곱하고, `hide`는 즉시 우선.

## 2. 연출 규칙

- **글자는 소리보다 0.2초 먼저** 낸다.
- **컷당 장식 1개, 화면 효과 1개**까지.
- **방향 교대**: 좌→우 다음은 상→하. 같은 방향을 연달아 쓰지 않는다.
- **강한 모션은 아낀다**: 반전·플래시·크래시 줌은 "키메" 줄(후렴 첫 줄, 느낌표 줄)에만.
- **파트 단위 통일**: 한 파트 안에서는 레이아웃·움직임·카메라·장식을 맞추고, 반복되는 가사는 처음과 같은 연출로 돌아온다.
- **조판**: 조사는 작게, 줄 첫 글자는 크게, 영문은 조금 크게 하고 한글·일본어와 간격을 둔다. 쌓기 레이아웃의 크기 대비는 최대 2.2배.
- **글자 모프**: 같은 줄의 다음 컷으로 넘어갈 때 같은 글자는 이동시키고 나머지만 녹인다.
- **가운데 비우기**: 캐릭터를 중앙에 둘 때 가사를 둘로 나눠 좌우 띠(각 폭 36%, 21:9는 30%)나 상하 띠(높이 33%)에 두고, 뒤쪽 절반을 조금 늦게 낸다.

## 3. 아이디어 목록 (JIZURA 키네틱 세트)

이름만 봐도 무엇인지 떠오르는 것들. 구현은 `src/11p_kinetic1~3.js`에 있다(MIT, 저작권 표시 유지 조건으로 코드 차용 가능).

- **레이아웃**: 쌓아 올리기, 직각 턴, 단어 교체, 글자 속으로, 흐르다 정렬, 시소, 타자→슬램, 단어 컷 분할, 루프 궤도, 톱니바퀴, 정면충돌, 굴러오는 상자, 세로에서 가로로, 패드
- **등장**: 단어 슬램, 타자→확대, 교체 등장, 경첩 내리기, 루프 등장, 밀어 넣기, 급브레이크, 단어 회전, 앞에서 단어, 쭉 늘이기
- **유지**: 단어 박자, 역회전 흔들기, 단어 파도타기, 째깍 이동, 박자에 기울기, 단어 간격 호흡
- **퇴장**: 단어 차내기, 밀어내기, 한 글자로 돌진, 급발진, 한 단어씩 소등, 좁히며 사라짐, 점프 컷, 쌓아서 떨구기
- **카메라**: 읽기 따라가기, 단어마다 기울기, 카드 뒤집기, 시어 킥, 점프 컷, 멀리서 돌진
- **전환**: 코너 스윙, 스터터 컷, 띠 슬램
- **장식·가공**: 따라오는 스피드 선, 단어 카운터, 크고 작은 단어, 단어별 반전

## 4. JIZURA 브라우저 앱으로 초안 뽑기

### 언제 쓰나

- 가사·대사처럼 줄 단위로 흘러가는 텍스트의 리릭 모션 초안이 빨리 필요할 때.
- 실사·AI 영상 위에 얹을 타이포 소재(투명 PNG, 블랙백)가 필요할 때.
- 구성 아이디어를 여러 개 넘겨 보고 싶을 때.

로고, 제품 프로모, UI 모션, 단어 하나하나를 의도대로 설계해야 하는 카피에는 쓰지 않는다. 그건 위 수치로 직접 만든다. 미감은 일본 보카로 PV 쪽으로 강하게 치우쳐 있다.

### 절차 (2026-10-09에 v0.10.1로 확인)

내장 브라우저(`mcp__Claude_Browser__*`)로 한다.

1. `https://852wa.github.io/JIZURA/ko/` 를 연다. 가사·음원은 브라우저 안에서만 처리된다.
2. 가사는 `#lyrics` 텍스트 영역에 넣는다. 한 줄이 한 프레이즈.
   - `/` 컷 구분, `*단어*` 강조, 줄 끝 `!` 플래시와 흔들림, `[01:23.45]` LRC 타임스탬프, `[간주 8]` 8초 간주, 빈 줄은 파트 구분.
3. 테마 선택 상자(값: `lyricpv`, `kinetic`, `wa`, `horror`, `pop`, `ballad`)에서 고른다. 키네틱 타이포는 `kinetic`.
4. 자동 생성 버튼(`#btnOmakaseTop`)을 누른다. 누를 때마다 스타일·분위기·배색·구성이 바뀌고, 토스트에 "자동 생성(키네틱): 스타일 × 분위기"가 뜬다. 이전·다음 버튼(`#btnPrev2`, `#btnNext2`)으로 안을 오간다.
5. 일부만 바꾸려면 `#eStyle`, `#ePalette`, `#eMood`, `#eCut`.
6. 출력 설정: `#eAspect`(화면비), `#eRes`(720p–4K), `#eFps`(24/30/60), `#eKey`(일반/그린 스크린/블랙백).
7. 내보내기: `#eMP4`, `#ePNG`(시퀀스 ZIP), `#ePNGA`(투명 PNG), `#ePNGL`(투명 전경/후경 분리), `#eLRC`. AE용 JSON은 메뉴 안의 `#btnAE`.

확인한 것은 3·4번(테마 선택, 자동 생성, 토스트)과 `J.uiApi.pause()`·`J.uiApi.seek(초)`까지다. 내보내기와 음원 불러오기는 눌러 보지 않았다.

### 알아둘 것

- **화면 폭**: 브라우저 패널이 좁으면 스마트폰 모드로 열린다. 모드 버튼은 `#modeMobile`, `#modeEasy`, `#modePro`. 줄별 잠금, 컷별 부품 교체, 코마 설정은 고급 모드에만 있다.
- **스크린샷**: 재생 중에는 스크린샷이 시간 초과로 실패한다. 먼저 `J.uiApi.pause()`와 `J.uiApi.seek(t)`로 멈춘다. 그래도 패널이 가려져 있으면 실패하므로, 그때는 사용자에게 패널을 앞으로 가져와 달라고 한다.
- **확인은 읽기로**: 생성 결과는 토스트 문구와 `#lyrics` 값으로 확인할 수 있다. 화면을 못 본 채로 "잘 나왔다"고 말하지 않는다.
- **내보내기는 다운로드다**: 누르기 전에 파일 종류·해상도·길이를 말하고 사용자 확인을 받는다.
- **음원**: `#audioFile`은 파일 선택이라 사용자가 직접 골라야 한다. 음원 없이도 글자 수 기준 자동 타이밍으로 만들어진다.
- **MP4**: WebCodecs가 필요하다. 안 되면 PNG 시퀀스로 뽑아 ffmpeg로 묶는다.
- **버전**: 앱은 자주 갱신된다. 요소 id가 달라졌으면 `find`나 `read_page`로 다시 찾는다.

### AE로 넘길 때

- CEP 확장판은 설치하지 않는다. 설치 스크립트가 서명 없는 확장을 전부 허용하도록 설정을 바꾼다.
- `JIZURA_AE.jsx`를 `파일 → 스크립트 → 스크립트 파일 실행`으로 돌려 JSON을 읽는다.
- 제작자가 실제 AE에서는 검증하지 않았다고 밝혔다. 몇 줄짜리 구간에 "경량" 옵션으로 먼저 시험한다.
- AE에서는 박자 싱크가 컷 길이 균등 분할로 바뀌고, 3D 회전·픽셀 가공·모프는 근사치가 된다.
- 레퍼런스를 분석해 AE에서 의도대로 짜는 작업은 `kinetic-type-ae` 스킬을 쓴다.
