# 제작 규칙

코퍼스의 상세 프롬프트들이 공통으로 요구한 것을 주제별로 모았다. 괄호 안은 출처 slug다.

## 1. 연출

**구조**
- 한 숏에 아이디어 하나. 장면마다 숨 쉴 여백을 둔다.
- 첫 1초 안에 훅. 첫 1.5초가 이미 고급스러워 보여야 한다. 제품의 의미 있는 첫 순간은 2초 무렵. 5초짜리 로고 인트로 금지.
- 15초에 시각 아이디어 약 4개. "평범한 기능 애니메이션 10개보다 비범한 순간 3개." 빠른 편집은 1.5–2초마다 새 아이디어.
- 기능 목록이 아니라 하나의 생각으로 이어지게 한다. 예: CHAOS → CONTROL → CLARITY → 브랜드.
- 마지막 프레임은 읽힐 만큼 멈춰 있어야 한다. 튀는 CTA로 끝내지 않는다.
- 리듬은 이야기에 따라 빨라졌다 느려진다. 최소 한 번은 400ms 이상의 완전한 정지를 둔다(gdgtify-929495).
- 중요한 프레임 하나하나가 정지 광고로 쓸 수 있는 구도여야 한다.

**전환** — 가장 중요한 부분으로 꼽혔다.
- "당연히 다음 장면은 저기서 나왔지"라는 느낌. 이전 장면의 물체가 다음 장면이 된다.
- 좋은 예: 차트 선 → 문서 모서리, 금색 알약 → 버튼, 숫자 → 다음 화면의 금액, 카드 모서리 → 다음 면, UI 요소를 뚫고 들어가는 카메라, 실제 제품 도형으로 만든 마스크, 검은 도형이 화면을 채웠다가 다음 장면으로 수축, 글자의 속공간(O)이 창이 되어 다음 구도가 보임.
- 나쁜 예: 크로스페이드, 무작위 와이프, 회전 전환, 글리치, 2초마다 휩 팬, SaaS식 슬라이드, 줌 블러 남발.
- 전환 하나에 주된 움직임 하나. 전환 자체가 기능을 시연하면 가장 좋다(howdevelop-733090).
- 직접 컷은 리듬상 의도가 있을 때만.

**움직임**
- 선형 이동 금지. 무게감 있는 이징, 예: `cubic-bezier(0.16, 1, 0.3, 1)`.
- 오버슈트는 2% 미만. 임계 감쇠 스프링이나 아주 작은 오버슈트. 만화 같은 탄성 금지.
- 요소마다 도착 시간이 조금씩 다르게(스태거, 오버랩). 전부 같은 프레임에 시작하고 멈추지 않는다.
- 예비 동작, 정착, 장면 간 속도 공유. 물리적 고급 제품을 매크로 촬영하듯 카메라를 움직인다.
- 카메라는 각 상태가 프레임을 채우도록 줌한다(화면 녹화 도구식). 무작위 드리프트 금지.
- 느리고 정제된 톤을 원하면: 카메라 이동 1.5–3초, 부드러운 ease-in-out, "기본으로 잡을 속도의 절반"(jake11moran-414633).

**글자**
- 카피는 아주 적게. 한 줄 3–4단어. 문장이 제품과 경쟁하면 안 된다.
- 나가는 글자가 완전히 사라진 뒤 들어오는 글자가 같은 자리를 쓴다. 겹침 금지.
- 변형되는 컨테이너 안에서 바뀌는 글자는 자기만의 입·퇴장 타이밍과 마스크가 필요하다.
- 글자는 설계된 물체처럼 움직인다. 단어마다 제각각 튀는 일반 모션그래픽 버릇을 피한다.
- 서체 역할을 나눈다. 예: 외침용 디스플레이 / 보조 그로테스크 / 작은 라벨용 모노. 디스플레이 자간 −40~−80, 모노 +20(techhalla-498547).
- 화면 글자는 구매자에게 하는 말이어야 한다. "squash", "easing" 같은 제작 용어를 화면에 쓰지 않는다. 스크러버·타임코드·fps 같은 크롬도 넣지 않는다(ik-builds-585923).
- 화면 글자에 마침표를 찍지 않는다(twoclipping-000267).

**색·질감**
- 팔레트를 엄격히: 3색 안팎, 강조색 하나. 브랜드색은 귀한 악센트로 쓰고 화면을 덮지 않는다.
- 검정에서 강조색으로 바로 페이드하지 않는다. 강조색 요소를 상태 사이로 이동시킨다(verbove-268381).
- 조명은 아주 약하게: 림 라이트, 은은한 블룸, 절제된 비네트. 영화처럼 보이려고 제품을 흐리게 하지 않는다.
- 인쇄 오프셋(색 어긋남 2–4px)은 임팩트 프레임에만.

## 2. 결정적 렌더링

상세 프롬프트 대부분이 같은 엔진 규칙을 요구했다.

- 모든 스타일을 `seek(t)`(또는 `draw(t)`) 안에서 **절대 시간으로부터 계산**한다. 어떤 순서로 프레임을 찾아가도 같은 결과가 나와야 한다.
- 금지: CSS transition/animation, `setTimeout`/`setInterval`, 프레임 간에 누적되는 상태, 누적 물리, 매번 바뀌는 난수. 난수가 필요하면 시드를 고정한다.
- `seek`는 async로 두고 이미지 디코드·비디오 `seeked`를 기다린 뒤 그린다.
- **스프링은 닫힌 형태의 계단 응답**으로 쓴다. 목표가 여러 번 바뀌는 값은 변화마다 스프링 하나씩을 더한다. 그러면 시간의 순수 함수로 남는다.
- 늘어나는 인디케이터: 양쪽 가장자리를 서로 다른 스프링에 태운다. 앞쪽이 먼저 나가고 뒤쪽이 따라온다. 토글 손잡이도 같다.
- 드래그는 직접 조작: 누른 동안 값은 커서 위치에서 계산하고, 놓으면 그 위치와 속도에서 스프링으로 돌아온다.
- 매치 컷은 요소 위치를 런타임에 측정해서 맞춘다.
- 루프: `render(0) = render(duration)`. 형태·내용·카메라·커서 위치와 속도까지 일치시킨다. `[0, duration)` 구간만 내보내고 끝 프레임을 중복하지 않는다. 가려진 순간에 숨은 요소를 초기 위치로 되돌린다.
- Remotion에서도 같다: 프레임 기반 interpolate/spring만 쓰고, 1,500줄짜리 단일 컴포넌트 대신 프리미티브(카메라 면, 제품 프레임, 마스크 전환, 텍스트 리빌, 공유 요소 전환)로 나눈다. 같은 코드에서 props로 언어판·길이·화면비를 바꿔 뽑는다.

**렌더 파이프라인**
- 헤드리스 Chrome(Playwright)으로 프레임 단위 캡처 → ffmpeg, H.264 + yuv420p.
- 모션 블러: 출력 프레임당 서브프레임 3–6장을 찍어 ffmpeg `tmix`로 블렌드. 정지한 글자와 아트워크는 선명하게 유지된다.
- 화면비 여러 개는 병렬로 내보낸다. 세로판은 크롭이 아니라 다시 구성한다.
- 실사 영상 소재: 전부 인트라 프레임으로 재인코딩(`ffmpeg -g 1`)해서 blob URL로 올리거나, 30fps JPEG 시퀀스로 뽑아 프레임마다 img를 바꾼다. `python http.server`는 범위 탐색이 안 된다.
- 에셋과 폰트는 파일 안에 넣어 렌더가 네트워크에 의존하지 않게 한다.

## 3. 사운드

- **비트 그리드가 뼈대다.** 120 BPM이 표준(프리미엄 톤은 115–120). "매 비트마다 무언가 일어난다." 스태거 간격도 음표 단위로(120 BPM의 16분음표 = 125ms).
- 길이를 마디로 맞춘다. 예: 96 BPM 8마디 = 정확히 20초. 120 BPM 7마디 = 14초.
- 음악을 받아 쓸 때: numpy로 템포·비트 그리드·마디별 에너지·드롭을 분석하고, 그리드를 실제 킥 위치에 보정한다. 다운비트에서 시작한다. 템포가 다르면 타이밍을 음악에 맞춘다.
- 음악 구조를 영상 구조에 묶는다: 줌이 드롭에 착지, 조용한 장면은 브레이크다운에, 로고 귀환은 비트 복귀에. 에너지 낮은 구간은 조용한 컷으로 쉬게 한다.
- **코드로 합성하는 경우:** Python으로 사인파와 노이즈에서 직접. 영상과 음악이 같은 비트 파일을 읽게 하면 모든 히트가 같은 프레임에 떨어진다(apoorvjain25-309680). 섹션별로 편곡을 바꾼다(어두운 전환에서 드럼이 빠지고, 타이포와 로고에서 다시 들어옴).
- SFX는 파일 시작점이 아니라 **측정한 피크**가 이벤트에 오도록 놓는다. 음악보다 조용하게.
- SFX 어휘: 낮고 부드러운 임팩트, 절제된 UI 클릭, 금속·유리 틱, 카메라 이동의 저역 움직임, 로고의 해결음. 피할 것: 트레일러 붐, EDM 라이저, 사방의 후시, 스톡 "테크 UI" 소리.
- 조용한 톤의 대안: 요소가 나타날 때마다 부드러운 SFX 하나, 나머지는 침묵(aschapmann-724497).
- 마스터: −14 LUFS, −2 dBTP. AAC 인코딩 후 다시 측정한다.
- 나레이션: TTS(ElevenLabs, Gemini TTS, edge-tts, 오픈소스 모델). 음성을 구절 단위로 쪼개 말하는 순간 화면과 자막이 나오게 동기화한다. 음악은 목소리 아래에서 덕킹한다.
- 저작권: 상업 이용이 허용된 음원만. 없으면 저작권 음악을 가져오지 말고 큐 시트를 남긴다. 출처를 기록한다.
- 모델은 소리를 듣지 못한다. 파형을 수치로 분석해서 맞춘다.

## 4. 검수 루프

- 본 렌더 전에 비트마다 한 프레임(또는 20장 이상)을 뽑아 컨택트 시트로 본다.
- 묻는 것: 템플릿처럼 보이는가? 화면에 너무 많은가? 제품이 읽히는가? 전환이 논리적으로 이어지는가? 모든 프레임이 구도를 갖췄는가? 글자가 잘리거나 겹치는가?
- 완성 MP4에서 디코드한 프레임을 다시 본다. 프레임 간 차이가 이웃의 3배로 튀는 지점(한 프레임 팝)을 스캔한다.
- 프레임 타임스탬프 간격과 전체 길이를 확인한다. 오디오 믹스는 수치로 잰다.
- **스스로 기각할 것:** SaaS 템플릿, 파워포인트 애니메이션, 웹사이트 화면 녹화, 스크린샷 다섯 장이 미끄러지는 것, 과한 마케팅 카피.
- 계획이 프로 디자이너의 것 같지 않으면 처음부터 다시 한다(heyiammallik-293397).
- 다중 에이전트 검수가 쓰인 사례:
  - 3회전 × 에이전트 3: 리뷰어 둘이 각자 문제 9–10개를 P0/P1/P2로 매기고 셋째가 고친다. P0는 전부, 나머지는 가치 있을 때만. 회전 전 백업, 후 스크린샷 확인, 못 고치면 롤백(voxyz-ai-345550).
  - 찾는 에이전트(높은 effort) → 만드는 에이전트(중간) → 심사 에이전트(높은 effort)가 한 번 평가. 심하게 나쁜 것만 되돌린다. 일괄 재작업 루프 금지(stokebuilder-356793).
  - 렌더 → 비전 모델이 VFX 감독처럼 지적 → 수정, 약 40회 반복(nathanwilbanks-981110).
- 사용자 피드백으로 효과가 컸던 말: "파워포인트 같지 않게", "더 juicy하게", "잘된 영상들을 링크할 테니 왜 그쪽이 더 나은지 분석해라".

## 5. 함정

- 카메라가 스케일하는 요소에 `will-change`를 걸면 글자가 흐려진다.
- `preserve-3d` 요소에 opacity나 filter를 걸면 평면화되어 양면이 다 보인다. 래퍼를 페이드한다.
- Chromium에서 `backdrop-filter: url()`은 변위 맵을 잘못 읽는다. 뒤 장면을 복제해서 필터를 건다.
- 화면을 채우는 플러드는 모서리 너머까지 과하게 키우고 약 0.3초를 준다. 아니면 한 프레임에 화면 절반이 바뀐다.
- `visibility: visible`인 자식은 숨긴 부모를 뚫고 보인다. `inherit`을 쓴다.
- 모든 from 상태를 t=0에 설정한다(seek 안전). 퇴장을 다른 요소로 덮지 않는다.
- 픽셀 아트: 낮은 논리 해상도(예: 128×96) 오프스크린에 그리고 정수 배율로 확대, 스무딩 끔, 정수 좌표, 고정 팔레트. 포즈 값은 부드럽게 움직이되 매 프레임 그리드에 양자화해 8–12fps 느낌을 낸다(majidmanzarpour-927543).
- 리퀴드 글래스: 유리 요소마다 뒤 장면 복제본을 갖고, SVG feImage 변위 맵(둥근 사각형 거리장)을 스케일이 조금씩 다른 feDisplacementMap 세 개로 통과시켜 색수차 가장자리를 만든다. 림 라이트 추가(twoclipping-496100).
- 구 형태(goo): 블러 + 알파 임계값 후 원본을 위에 합성해 안쪽을 선명하게.
- 컷아웃 애니메이션은 15fps(on twos)로 움직이면 콜라주 느낌이 산다.

## 6. 2026-10-21 코퍼스 갱신에서 더한 규칙

새 프롬프트 258개에서 여러 제작자가 반복해 쓴 것만 모았다. 괄호는 대표 slug.

**움직임**
- 카메라는 멈추지 않는다. 유지 구간에도 1.03~1.07배로 천천히 민다. 아무것도 "뿅" 하고 나타나지 않는다(글자는 마스크 선을 지나 한 자씩 올라온다). 무늬는 박자에 맞춰 한 칸씩 돌지 말고 계속 돈다(twoclipping-551116).
- 빨리 와서 부드럽게 앉는다: 남은 거리의 12~19%를 매 프레임 이동(notdwd-766641). 2~4프레임 스태거, 블러는 빠른 이동에만.
- 확대와 축소를 연달아 하지 않는다. 한 장면에 카메라 이동 하나. 줌은 로그 공간에서 보간(ultimaxbt-549714).
- 넘겨받는 물체(shared element)는 컷 양쪽에서 **같은 픽셀**에 놓인다. 변형은 떠나는 장면과 같은 카메라 변환 안에서(everestchris6-399895, twoclipping-551116).
- 커서: 프레임당 65px 이하, 목표가 "도착할 위치"를 겨냥, 루프 경계에서 위치·속도까지 첫 프레임과 일치(flxrnc-251921).
- 읽기: 현재 읽는 구절은 1080 기준 64px 이상, 읽기 정지가 끝나기 전에는 장식 이동을 시작하지 않는다, 모션 블러는 읽는 글자에 걸지 않는다(gdgtify-989608).

**구성**
- 첫 프레임은 완성된 그림이다. 글자가 날아오는 중간이 아니다.
- 30초에 구도 12~15개, 각 1.4~3.5초가 "광고·런치" 계열의 기준(everestchris6-399895). 빠른 편집형의 60~80개(workflow.md)와 다른 장르 기준이다.
- 모든 행동은 보이는 결과를 낸다: 스캔하면 발견이, 탭하면 새 상태가, 요청하면 확인이 나온다.
- 3D는 물리·공간을 설명할 때만. 카메라 각도 35~55°, 큰 평면을 정수직으로 내려다보지 않는다, 라벨은 3D 안 글자가 아니라 3D 위치에서 매 프레임 계산한 HTML. 렌더된 배경 픽셀을 재서 브랜드 색과 맞춘다.

**검수(독립 비평)**
- 만든 쪽이 스스로 판정하지 않는다. 스토리보드·부품·전체 렌더마다 만든 과정을 모르는 새 비평 에이전트에게 렌더·브리프·레퍼런스만 준다. **무엇을 고쳤다고 생각하는지 말하지 않는다.** 비평은 0.2초 간격 시트 + 전환 주변 촘촘한 프레임을 직접 뽑고, 정지 시간·음량을 재서 시간이 적힌 순위 목록과 "출고 / 한 번 더"로 답한다. 다음 비평은 이전 항목을 고침 / 일부 / 그대로로 확인하고 새로 깨진 것을 찾는다. 회차마다 장부를 남긴다(everestchris6-399895).
- 수치 기준: 30초당 정지 화면 합계 약 1초 이하, 0.5초 넘는 정지 구간 없음(의도한 쉼표 제외), 글자 대비 4.5:1 이상, 글자끼리 충돌 없음.
- 거친 감독처럼 스틸 5장을 비평하고 가장 나쁜 3개를 고친 뒤 렌더(notdwd-766641). 각 박자의 스틸을 1~10점으로 매기고 가장 낮은 것부터(ulyssexbt-205279).
- 루프 이음매 검사: 0번 프레임과 마지막+1 프레임을 비교해 한 픽셀이라도 다르면 주기적이지 않은 움직임이 있다(0xkarmi-129839).

**함정**
- 아이리스(원형 열림·닫힘)는 반지름이 아니라 면적으로 이징. 화면 밖 점으로 카메라를 줌하면 옆으로 휘며 튄다 → 점을 "연다".
- globalAlpha를 바꾸는 도우미는 호출자의 값을 복원한다. 안 하면 페이드 중인 카드가 튄다.
- 카운터·타이핑은 서브프레임 시간이 아니라 프레임 시간으로 읽는다. 안 하면 숫자가 번진다.
- 빠른 휩은 서브프레임 4장으로는 잔상이 남는다 → 8장.
- 화면을 덮은 큰 원 레이어는 다 덮은 뒤 전체 사각형으로 바꾼다(아래로 미끄러져도 계속 덮는 문제).
- 헤드리스 Chromium에서 WebGL이 안 그려지면 `--use-angle=swiftshader`.
- 색 분리(chroma fringe)는 가장자리를 클램프한 이동으로(테두리 번짐 방지).
